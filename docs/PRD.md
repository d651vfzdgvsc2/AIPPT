# DeckCraft：参考图驱动的 AI 演示设计工作流

**产品需求文档（PRD）**

| 项目 | 内容 |
|---|---|
| 文档版本 | v2.0 |
| 日期 | 2026-10-05 |
| 状态 | 已实现（React + Flask，可直接产出 .pptx） |
| 前身 | Prompt 定制助手（只输出提示词文本） |

---

## 1. 项目概述

DeckCraft 把「一张参考图或一句话需求」变成**可下载的 PPT**：

```
参考图 / 需求 →（拆解）可编辑的设计规范 →（生成）演示大纲 →（渲染）直接产出 .pptx → 下载
```

设计哲学：**精确的事交给算法（提色 / 渲染），理解的事交给 AI（风格 / 大纲），经验沉淀为可复用规范（Skill 化）。**

## 2. 背景与问题

非设计用户制作 PPT 时：

- 能说清"想要什么感觉"，却难以把它转成**可执行的设计规范**；
- 反复试错、出稿慢、风格不稳定；
- 设计经验（配色 / 版式）无法沉淀复用；
- 市面上多数"AI 做 PPT"工具只给一段文本提示词，用户还得自己去做。

**核心矛盾**：用户要的不是"一段文本"，而是"**一份能打开、能用的 PPT**"。

## 3. 目标与非目标

**目标**：参考图/需求 → 结构化的设计规范 → 直接产出可打开的 `.pptx`；规范可编辑、可复用。

**非目标**（本期）：不做在线协同编辑；不做复杂动画/母版；不保证像素级还原参考图。

## 4. 目标用户与场景

| 用户 | 场景 |
|---|---|
| 办公 / 学生 | 工作汇报、教学课件、年终总结 |
| 创业 / 商务 | 产品发布、路演融资 |
| 非设计背景 | 手上有参考图，想快速得到风格统一的 PPT |

## 5. 名词定义

| 名词 | 说明 |
|---|---|
| 设计规范 | 由参考图拆解出的配色 / 版式 / 字体 / 强调色用法，**可编辑** |
| 主色提取 | OpenCV k-means 从参考图提取主色（确定性，不靠模型） |
| 大纲 | 大模型生成的演示结构（标题 + 逐页要点，严格 JSON） |
| Skill 化 | 设计规范可保存、可复用，作为可沉淀的资产 |

## 6. 总体架构

```
前端    React + Vite + Tailwind（需求 / 上传压缩 / 设计规范 / 结果 / 历史）
后端    Flask：/analyze · /deck · /generate/stream · /health
核心    design.py：k-means 提色 + 视觉模型风格拆解 + 大纲生成 + python-pptx 渲染
模型    DeepSeek 视觉模型（风格理解 / 大纲）
```

## 7. 功能需求（FR）

| 编号 | 功能 | 描述 | 优先级 | 验收标准 |
|---|---|---|---|---|
| FR1 | 需求输入 | 文本输入 + 模板 chips 一键填充 | P0 | 空需求 + 无图时给出提示 |
| FR2 | 参考图上传 | 支持拖拽 / 选择；前端压缩（最长边 1280 / JPEG 85%） | P0 | 大图压缩后上传，体积可控 |
| FR3 | 参考图拆解 | `/analyze`：k-means 提主色 + 视觉模型理解主题 / 版式 / 字体 | P0 | 返回配色数组 + 风格字段 |
| FR4 | 设计规范可编辑 | 配色色板 + 主题 / 版式 / 字体 / 强调色均可编辑 | P0 | 编辑后的规范参与后续生成 |
| FR5 | 大纲生成 | 依据需求 + 规范生成演示大纲（标题 + 逐页要点 JSON） | P0 | 6~10 页，要点精炼 |
| FR6 | 产出 .pptx | `/deck`：python-pptx 依规范渲染，直接下载 | P0 | 下载文件可被 PowerPoint 打开 |
| FR7 | 生成 Prompt | `/generate/stream`：SSE 流式输出提示词文本（保留能力） | P1 | 逐字显示，可复制 |
| FR8 | 再优化一版 | 携带上一版作为上下文迭代 | P2 | 结果基于上一版改进 |
| FR9 | 历史记录 | localStorage 保存最近 20 条 | P2 | 可点击回填、可清空 |

## 8. 非功能需求（NFR）

- **安全**：API Key 仅从 `.env` 读取；`.env` 被 `.gitignore` 忽略；只监听 `127.0.0.1`；单 IP 限流；请求体上限 20MB；图片前端压缩。
- **质量**：主色提取为确定性算法（可复现）；风格与大纲由模型负责，失败时降级不崩。
- **可维护**：前端（React）与后端（Flask）分离；设计工作流核心集中在 `design.py`。
- **交付**：前端构建产物由 Flask 托管；`templates/index.html` 作为回退。

## 9. 接口

| 接口 | 方法 | 入参 | 返回 |
|---|---|---|---|
| `/` | GET | — | 前端页面（React 构建产物） |
| `/health` | GET | — | `{ status, api_key_configured, model }` |
| `/analyze` | POST | `{ image_base64 }` | `{ success, palette[], style{} }` |
| `/deck` | POST | `{ user_input, image_base64?, spec? }` | `.pptx` 文件下载 |
| `/generate` | POST | `{ user_input, image_base64?, previous_prompt? }` | `{ success, prompt }`（兼容） |
| `/generate/stream` | POST | 同上 | SSE：`{delta}` … `{done}` / `{error}` |

## 10. 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 18 + Vite + Tailwind CSS |
| 后端 | Python 3.10+、Flask |
| 图像 | OpenCV（k-means 主色提取） |
| 大模型 | DeepSeek 视觉模型 |
| 文档生成 | python-pptx |
| 通信 | SSE（`text/event-stream`） |

## 12. 风险与边界

- 产出为**由规范渲染的初稿**，非像素级还原参考图；需人工微调。
- 依赖视觉模型：偶发限流 / 失败时走降级（保留主色，大纲兜底）。
- 复杂版式（自定义图形 / 动画）不在本期范围。
